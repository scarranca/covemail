# Cove 0.1.45 — automatic older-mail loading and cloud snoozes (published)

September 26, 2026. Cove 0.1.45/build 47 is published at covemail.xyz. The snooze backend and Mac distribution were released with user approval; see the rollout records below. No installation or running-app replacement was performed.

## Behavior

The permanent Load older mail button is removed. A footer inside the mail list observes its actual position in the scroll viewport; reaching the end loads the next page through the existing mailbox or independent label/flag cursor. Lazy row creation alone does not load pages. Loading shows a small inline indicator. Concurrent requests, busy work, pending Trash, sample mode, disconnected accounts, and exhausted cursors are guarded. A failed page requires explicit Try again; geometry changes do not retry it indefinitely. If a page adds no messages matching the local filter, automatic continuation pauses until another scroll, preventing an unattended full-mailbox download. Folder, search, sort, and unread/priority changes reset the viewport trigger. Selection and existing downloaded messages are preserved.

Remind me saves locally and, with cloud sync enabled, queues a separate server snooze record. The implementation below supersedes the initial local-only behavior; the backend and Mac 0.1.45 are now published. Users must install the update and enable the optional cloud pilot to sync snoozes. It is not a notification or Gmail-side snooze. Inbox messages disappear from Cove’s Inbox while their local snooze time is in the future and remain accessible in Snoozed. Once due they reappear in Inbox if they still carry the INBOX label; other filters continue to apply. Cove updates its local clock while open. No background notification is scheduled. The reader’s Tomorrow morning action now means the following calendar day at 9 a.m. local time, correcting the previous next-occurrence-of-9-a.m. behavior before 9 a.m.

## Server snoozes — implementation and pre-deployment verification

The user's subsequent request moves snooze state to the server for future mobile notifications. Added `backend/migrations/002_snoozes.sql`, independent PUT/change-feed endpoints, `CloudSnoozeState`, and an encrypted per-account Mac outbox. Reminder timestamps and message/thread IDs are queryable PlanetScale metadata, isolated by forced RLS. They survive the 30-day/1,000-message mail-mirror window and do not upload the old email's subject/body. `wakeAt: null` is a retained cancellation; dates use absolute UTC, while Tomorrow morning is calculated in the local calendar before conversion.

Request UUIDs and payloads are durably frozen before upload. Response loss/restart repeats the exact request; a newer local reschedule/cancellation waits behind it. Per-record base revisions reject concurrent stale writes. The client keeps conflicting local intent and asks for an explicit new snooze/cancel action. Local mail changes and received snooze pages/cursors persist atomically with their queue/state. Pending state wins over remote pages; replayed old receipts cannot replace newer server records. Confirmed Gmail deletion and downloaded Trash/Spam states queue cancellation; mirror eviction alone does not. Cloud changes are retained for messages downloaded later.

Opt-in/default-off behavior is preserved. Existing future local snoozes bootstrap if absent remotely. Disabled/paused cloud sync leaves a local durable queue; no cloud auth/request occurs. While open, cloud polling runs about every two minutes independently of Gmail polling, scheduled without blocking the 30-second UI clock loop. Reminder changes are handled ahead of bulk mail uploads; reminder errors leave an explicit pending/error status while mail uploads can proceed. Menu/settings copy distinguishes local/pending/synced/conflict and says notifications are not available yet. Removing the cloud account cascades its snoozes; pause/disconnect retains them. The pilot caps snoozes at 5,000 records including cancellations and retains them until cloud-account removal.
